# 分栏对齐与滚动性能优化设计

## 背景

当前分屏模式存在三类相互关联的问题：

1. 预览区没有编辑模式切换行，且正文顶部内边距与块编辑器不同，导致预览首个内容块明显高于编辑区。
2. 双向滚动虽然已经使用 `requestAnimationFrame` 和缓存锚点，但几何观察器在持续时间超过 80ms 的布局变化期间仍会安排全量源码锚点扫描。
3. 分栏拖动虽然每帧只写一次 `flex`，宽度变化仍会触发编辑器、预览文档和滚动锚点系统共同参与布局，长文档时卡顿明显。

本设计采用“热路径隔离”方案：保留实时分栏和逐帧滚动，不引入拖动指示线、内容快照或文档虚拟化。

## 目标

- 编辑区与预览区首个内容块的垂直位置误差不超过 1px。
- 编辑区和预览区继续双向、逐帧同步滚动。
- 每个动画帧最多处理一次滚动同步和一次分栏位置更新，始终以最新请求为准。
- 分栏拖动期间不重建源码滚动锚点；松手后只重建并校准一次。
- 保持拖动期间文字实时换行，不隐藏内容，不使用缩放或模糊快照。
- 不改变 Markdown 解析、预览渲染、编辑控制器和持久化格式。

## 非目标

- 不实现预览或编辑器的块级虚拟化。
- 不改成“松手后才改变宽度”的幽灵分隔线模式。
- 不重写 Monaco、ProseMirror 或 Markdown 渲染器。
- 不改变沉浸模式、校对面板和聊天面板的产品行为。

## 方案选择

### 方案 A：热路径隔离（采用）

保留当前实时交互，通过共享尺寸变量、最新请求调度器和拖动期几何冻结降低主线程工作量。改动集中，可延续现有滚动锚点算法。

### 方案 B：轻量拖动层（不采用）

拖动时仅移动分隔线或缩放快照，松手后重排。性能最好，但不满足内容实时跟随和实时换行要求。

### 方案 C：文档虚拟化（不采用）

只布局可视块。长文档性能上限最高，但会显著增加锚点、图片、Mermaid、表格和选择行为复杂度，超出本轮范围。

## 详细设计

### 1. 统一顶部内容基线

编辑区的内容起点由“编辑模式切换行 + 正文顶部内边距”构成，预览区目前只有正文内边距。设计引入共享 CSS 尺寸：

- `--editor-mode-row-height`：模式切换行占用的固定高度。
- `--document-content-top-padding`：编辑与预览正文共用的顶部内边距。

编辑模式切换行使用固定盒模型高度。预览工作区增加同高、不可交互、对辅助技术隐藏的占位行。块编辑滚动容器和预览文档均使用相同正文顶部内边距。固定结构替代按标题字号或运行时测量补偿，避免主题、字体或窗口宽度变化造成偏移。

空文档提示仍以各自内容区域为基准，不受占位行影响。固定工具栏启用时，现有 `preview-toolbar-offset` 继续与编辑工具栏成对出现。

### 2. 最新请求滚动调度器

滚动控制器继续使用源码锚点插值，但热路径只做以下工作：

1. 接收编辑区或预览区的滚动通知。
2. 覆盖尚未执行的旧请求，仅保留最新来源、目标、锚点引用和缓存范围。
3. 若当前没有动画帧，安排一个 `requestAnimationFrame`。
4. 帧回调读取当前 `scrollTop`，通过缓存范围和锚点二分插值计算目标位置。
5. 仅在差值达到阈值时执行一次立即滚动。

滚动帧内禁止调用 `getBoundingClientRect()`、遍历 DOM 或读取 `scrollHeight/clientHeight`。程序滚动目标继续记录在映射中，目标栏产生的反馈事件会被识别并丢弃，防止往返回弹。

滚动调度从 `App` 中提取为独立、可销毁的控制单元，公开“提交最新请求”“取消待处理帧”“销毁”三个最小操作，以便单元测试验证帧数量和覆盖语义。

### 3. 锚点缓存生命周期

锚点重建只允许由以下事件触发：

- Markdown 预览完成一次新渲染。
- 图片、Mermaid 或文档内容产生稳定尺寸变化。
- 编辑器控制器或活动文档发生变化。
- 分栏拖动结束。
- 浏览器窗口完成尺寸变化后的合并刷新。

`ResizeObserver` 只负责标记几何缓存失效，不直接执行全量扫描。多个失效通知合并到一个延迟任务。进入面板拖动状态后，失效标记保留，但不安排扫描；退出拖动时在下一动画帧重建一次锚点和滚动范围，并以当前编辑区位置重新对齐预览。

全量重建仍沿用当前源码行去重和首尾锚点逻辑。滚动过程中不会重建。

### 4. 实时分栏拖动

拖动开始时：

- 一次性读取容器边界和可用宽度。
- 进入 `panel-resizing` 状态。
- 暂停锚点重建和非必要尺寸校准。
- 禁用面板过渡和内部命中测试。

拖动过程中：

- `mousemove` 只覆盖最新 `clientX`。
- 每个动画帧最多计算一次比例并直接写入左右面板 `flex`。
- 与上一帧宽度差小于 1px 时跳过写入。
- 不调用 React/Zustand setter，不持久化设置，不读取新的容器边界。
- 编辑器和预览仍按真实宽度布局，文字实时换行。

拖动结束时：

- 若存在未执行的指针位置，先同步提交最后一帧。
- 将最终比例写入状态并持久化。
- 清理拖动光标、选择禁用和临时缓存。
- 恢复几何观察器，在下一帧重建一次滚动锚点并保持当前章节位置。

侧栏、校对和聊天宽度拖动沿用同一调度器语义，避免四组鼠标处理器产生不一致行为；本轮重点验收编辑/预览主分隔条。

### 5. 布局与绘制约束

拖动期间继续使用面板级 `contain: layout paint` 和 `pointer-events: none`，并关闭所有宽度、flex 和布局过渡。删除或避免暗示 `flex/width` 可在合成器独立完成的错误假设；这些属性仍会触发布局，因此性能收益来自减少更新次数和暂停额外几何工作。

不对正文使用 `content-visibility`，因为滚动锚点需要稳定的完整文档几何；不对文本层使用 transform，避免模糊和坐标失真。

## 数据流

### 用户滚动

`scroll event` → 覆盖待处理同步请求 → 下一动画帧读取缓存位置 → 锚点插值 → 标记程序滚动目标 → 立即设置目标栏 `scrollTop`。

### 用户拖动分隔条

`mousedown` → 捕获边界并冻结几何重建 → `mousemove` 覆盖最新指针 → 每帧一次 flex 写入 → `mouseup` 提交最终比例 → 下一帧一次锚点重建与滚动校准。

### 内容或媒体改变尺寸

`Preview rendered / ResizeObserver` → 标记几何失效 → 非拖动状态下合并调度 → 一次锚点重建 → 保持当前编辑位置。

## 异常与清理

- 组件卸载时取消滚动帧、拖动帧、锚点刷新计时器和观察器。
- 拖动过程中窗口失焦或鼠标在窗口外释放时，按结束拖动处理，提交已知最后位置并恢复页面状态。
- 若预览或编辑器不可滚动，继续回落到顶部位置。
- 若锚点尚未建立，按缓存滚动范围做比例同步；不得在滚动热路径临时扫描 DOM。
- `ResizeObserver` 缺失时由预览渲染版本、窗口 resize 和拖动结束事件保证重建。

## 测试与验收

### 自动测试

- 调度器在同一帧收到多个请求时只执行最新请求。
- 连续双向请求不会执行过期方向。
- 取消或销毁后不再执行帧回调。
- 拖动期间只记录几何失效，不执行锚点重建；结束后只执行一次。
- 最后一条鼠标位置在松手时不会丢失。
- 顶部尺寸变量、预览占位行和统一正文内边距存在且一致。
- 现有滚动锚点插值、顶部/底部映射和程序滚动过滤测试继续通过。

### 浏览器验收

- 编辑区与预览区首个标题顶部误差不超过 1px。
- 长文档从编辑区和预览区分别连续滚动，另一栏逐帧跟随且无回弹、追赶或抖动。
- 连续拖动主分隔条，内容实时换行，分隔条不明显落后指针。
- 拖动期间锚点重建次数为 0；松手后为 1。
- 表格、任务列表、代码块、Mermaid、公式、HTML 保真块和图片文档均不破坏同步。
