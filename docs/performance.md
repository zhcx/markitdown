# 长文档性能基线

本项目以桌面端生产构建、常规办公电脑（4 核 CPU / 16 GB 内存）为基线。性能检查应在关闭开发者工具、重复执行 3 次后记录中位数。

| 场景 | 目标 | 测量方式 |
| --- | --- | --- |
| 打开 1 MB Markdown | 首次可编辑 ≤ 1.5 s | 从选择文件到编辑器可输入 |
| 10 万字文档输入 | P95 输入延迟 ≤ 50 ms | 连续输入时 Performance 面板的键盘事件到绘制 |
| 1,000 文件目录 | 首层展示 ≤ 500 ms | 从确认文件夹到首层文件树可见 |
| Mermaid 图表 | 单图首次可见 ≤ 800 ms | 图进入预览区域到 SVG 显示 |
| 内存占用 | 打开 1 MB 文档后稳定 ≤ 350 MB | 系统任务管理器的应用进程 |
| AI 面板打开 | 编辑帧率 ≥ 55 FPS | 长文档中打开/关闭面板并拖动分栏 |

| 100 KB Markdown 块模式 | 首次可输入 ≤ 1.5 s | 从打开标签页到块编辑器首次可输入 |
| 10,000 个块连续输入 | P95 输入延迟 ≤ 50 ms | 连续输入 100 次字符并记录 Performance 面板 |
| 高级 Markdown 降级 | 自动进入源码模式 | 表格、公式、Mermaid、HTML 文档打开后检查编辑器模式 |

## 已落实的策略

- 编辑内容使用 React 延迟值驱动预览，输入优先于 Markdown 解析、代码高亮与公式渲染。
- Mermaid 使用 `IntersectionObserver` 延迟加载；只有接近预览可视区域的图表才会导入并渲染。
- 文件夹采用按层加载：展开目录时才读取子级，避免一次性递归扫描。
- 分栏拖动已通过 `requestAnimationFrame` 合并 DOM 写入，并在拖动结束后再同步全局状态。
- 预览滚动同步使用动画帧与阈值，减少长文档滚动时的布局计算。

## 后续触发条件

当任一指标超过目标时，再按瓶颈启用下一阶段改造：

1. 文件树超过 2,000 个可见节点时，引入虚拟列表。
2. 已打开文档搜索超过 10 万行时，改为 Web Worker 增量索引。
3. 大纲解析超过 16 ms 时，移入 Web Worker 并做增量更新。
4. 高亮代码块总量明显影响预览时，改为可见区域高亮。

## 分栏与滚动热路径

- 双向滚动采用 latest-frame 策略：同一动画帧中的旧请求由最新请求覆盖。
- 滚动帧只使用缓存范围和源码锚点，不读取 DOM 几何。
- 分栏拖动实时更新面板宽度，但拖动期间暂停源码锚点重建。
- 松手后提交最后指针位置，并只执行一次几何重建与滚动校准。
- 编辑区与预览区滚动定位采用相对锚点映射，不依赖共享顶部内边距。
- 每个预览块建立"首行 top + 末行 bottom"双锚点：代码块、表格、长段落等跨多行块的两端都被钉住，块内滚动按两端比例插值，避免中段漂移。
- 行布局按块的真实行数 `lineTo - lineFrom + 1` 插值（而非少算一行的 `lineTo - lineFrom`），保证末行 bottom 精确落在块底；否则多行块的 content-bottom 锚点会被推后，编辑框到底时预览尾部仍有小段内容滚不到位。Monaco 侧（开启 wordWrap）用下一行顶部作为本行底边，避免折行行高被低估。
- 锚点中额外对齐"内容底部"：编辑区最后内容贴底时预览区最后内容同步贴底（两侧都按"文档坐标 - 视口高"对称计算，不依赖尾部元素是否带行标记），尾部留白再按比例滚到滚动终点。
- 滚动同步每帧实时刷新两端滚动范围与末尾锚点：预览内容异步撑高（图片加载、Mermaid/KaTeX 渲染、字体回流）后，编辑器滚到底时不再用过期的预览最大滚动值，预览尾部内容不再被截断。
- 锚点重建批量查询编辑器行布局（一次 DOM 扫描 + 二分），避免每个锚点单独查块映射导致的长文档 O(n²) 卡顿。
- 编辑区滚动监听使用 `passive: true`，滚动手势不阻塞主线程判断 preventDefault。
